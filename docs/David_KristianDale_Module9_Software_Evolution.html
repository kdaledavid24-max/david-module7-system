Change Request — CR-M9-01

Change Request ID: CR-M9-01

Title: Add Multi-Status & Category Food Order Filter

Maintenance Type: Perfective Maintenance

Problem / Opportunity

The current FoodFlow Food Ordering System displays food order records but does not provide a filter that allows users to quickly view records according to their preparation status. As the number of food orders increases, kitchen staff and managers may need a faster way to distinguish pending, preparing, ready, and delivered orders from cancelled items.

Desired Outcome

Add an All, Pending, Preparing, Ready, Delivered, Available, and Cancelled filter to the food records section. The filter should allow users to quickly view food records by status while preserving the existing CRUD, search, validation, delete confirmation, and localStorage functionality.

Acceptance Criteria

  1. The food records section provides All, Pending, Preparing, Ready, Delivered, Available, and Cancelled filter options.
  2. Selecting Pending displays only food records marked as Pending.
  3. Selecting Delivered displays only food records marked as Delivered.
  4. Selecting All displays all food order records.
  5. Existing Add, Display, Edit, Delete, Search, Validation, Delete Confirmation, and Persistence functions continue to work correctly.

Impact Analysis

Architecture

The existing FoodFlow Food Ordering System architecture will remain unchanged at the overall system level. The food record list and filtering flow will be updated to support multi-status and category filtering using reactive computed properties in Vue.js.

Design / User Interface

An interactive status pill filter control (All, Pending, Preparing, Ready, Delivered, Available, Cancelled) and a category dropdown selector will be added to the food records section. The new controls will follow the existing visual design and responsive layout.

Implementation

The food order handling logic in App.vue and RecordList.vue will be updated to support status values and filtered results using Vue 3 Composition API. A safe schema normalizer (normalizeRecords()) will be added to handle older stored records on mount.

Data / localStorage

Existing food records must remain readable after the change. Records that do not yet contain a status value will receive a safe default of Pending so that previously stored data continues to function without errors or data loss.

Testing

The Module 8 baseline tests will be fully retained as regression tests. New test cases will verify status filtering, category filtering, combined keyword searching, and schema normalization. The final test plan will contain 14 manual test cases and 11 automated Vitest unit tests.

CI / Build

The project will be verified using npm run test:run and npm run build. GitHub Actions will also be checked to confirm that the evolved version passes all automated workflow steps before deployment.

Documentation

The architecture documentation, manual test cases, README.md, release notes, and this final evidence PDF will be updated to reflect the implemented changes in CR-M9-01 and release version 1.1.0.
