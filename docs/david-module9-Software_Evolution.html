6 Design and Working Implementation

Key Implementation Code: Safe LocalStorage Normalization (App.vue)

const normalizeRecords = (storedData) => {
  if (!Array.isArray(storedData)) return []
  return storedData.map(record => ({
    id: record.id || Date.now().toString(),
    customerName: record.customerName || 'Anonymous',
    foodName: record.foodName || 'Food Item',
    category: record.category || 'General',
    price: Number(record.price) >= 0 ? Number(record.price) : 0,
    status: record.status || 'Pending', // Safe default for older saved records lacking status
    image: record.image || null,
    ...record
  }))
}

Key Implementation Code: Multi-Facet Reactive Filter Engine (App.vue)

const filteredRecords = computed(() => {
  const keyword = searchTerm.value.toLowerCase().trim()
  
  return records.value.filter(record => {
    const matchesKeyword = !keyword || (
      record.foodName?.toLowerCase().includes(keyword) ||
      record.category?.toLowerCase().includes(keyword) ||
      (record.customerName && record.customerName.toLowerCase().includes(keyword))
    )

    const matchesStatus = selectedStatus.value === 'All' || 
      (selectedStatus.value === 'Ready' && (record.status === 'Ready' || record.status === 'Available')) ||
      (selectedStatus.value === 'Cancelled' && (record.status === 'Cancelled' || record.status === 'Unavailable')) ||
      record.status === selectedStatus.value

    const matchesCategory = selectedCategory.value === 'All' || record.category === selectedCategory.value

    return matchesKeyword && matchesStatus && matchesCategory
  })
})

10 Module 9 Knowledge Check Answers

1. Why must Module 9 reuse the same system from Modules 6 to 8?
Answer: Software evolution is the discipline of modifying an established, working baseline. Reusing the same system ensures practical experience in preserving architecture, protecting stored user data, and guarding against regression.

2. What is the difference between corrective and preventive maintenance?
Answer: Corrective maintenance fixes existing runtime defects or bugs discovered during testing or user operation. Preventive maintenance refactors internal code structure to reduce technical debt and simplify future changes without altering observable behavior.

3. Which artifacts should be examined during impact analysis?
Answer: Architecture diagrams, UI/UX layouts, Vue source components, localStorage storage schemas, manual and automated test suites, CI/CD build scripts, and release documentation.

4. Why must the Module 8 test baseline be retained?
Answer: The Module 8 test baseline serves as the primary regression safety net, verifying that new changes did not break existing CRUD and persistence functionality.

5. When should a backward-compatible feature increment the MINOR version?
Answer: Under Semantic Versioning (SemVer), a MINOR increment (e.g. 1.0.0 to 1.1.0) is mandated whenever new functionality or capability is added in a backward-compatible manner.

6. What evidence proves that an evolved system did not introduce regression?
Answer: 100% passing results across the complete manual test suite, green automated Vitest unit/regression tests, successful production builds, and passing CI workflows.
